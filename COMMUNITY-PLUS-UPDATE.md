# Gather 0.8.1 — Community Plus

Viewer layout: viewers can choose any available speaker camera as the largest box, or use equal boxes. Choices affect only their own screen. The host/moderator’s featured-speaker selection overrides personal choices for everyone; clearing it restores personal choice. Camera-off speakers have no video box to enlarge. Native live sessions use the browser studio for this control.

This release includes the previous purple/lime interface, Sparks, podcasts, privacy settings, contacts and Discord changes.

## New functions

- Shop listings: up to six pictures plus one processed video. Pictures can be removed before saving. Videos show upload progress and processing checks. Sellers own their attached media; unapproved media stays restricted to its owner and reviewing administrators. Approved videos use signed playback; blocking and archiving restrict future media access. Shopping, resale, merch and trade listings use the same attachment form. Existing one-photo listings remain compatible.
- Shop → Gifts: six original interactive gift previews: Spark, High Five, Bloom, Spotlight, Orbit, Gather Crown. Proposed costs: 5, 25, 100, 250, 500 and 1,000 GC. Tap to animate. Purchasing/sending is disabled on both client and server until real GC balances, payment purchases and creator payouts are implemented. These are animation previews, not purchasable inventory or live gift events.
- Public interest Gatherings: Gaming, Fishing, Beauty, Gardening, Music, Fitness, Food & Cooking, Sports, Books & Learning, Creators & Projects, Tech & Business. Created idempotently when the Gathering list is opened after the official page or configured admin account exists. Admin panel also has “Create public interest Gatherings.” They are open to join; no automatic member enrollment.
- Gathering profile pictures: owner/moderator uploads a picture from Gathering controls. Private Gathering pictures respect membership access.
- Membership applications: owner/moderator can require an application even in a public Gathering. The applicant submits at least ten characters and remains pending until approved. Moderators can review answers and approve or reject/remove; rejection uses the existing removal/ban behavior. Existing private groups still require approval without an application.
- Gathering reminders: moderators schedule a title, details and local date/time. Members see upcoming/recent reminders, receive an in-app notification when created and when due, and can independently enable a local device alert. Phone permission is requested on explicit enable. Browser alerts need the page to remain open; native scheduled alerts follow OS permission/battery rules. These are notification reminders, not forced full-screen alarms. Cancellation on the server does not revoke already scheduled alerts on other offline devices: members must cancel their own alerts. No remote push infrastructure is included. Server delivery is deduplicated; a stopped server delivers overdue in-app reminders when it next starts/receives a community request.
- Voice parties: approved Gathering members can start or join a microphone-only room with up to eight speakers. There is no public anonymous room token. Participants must join before getting media credentials. Host ends the room; members can leave. Microphones start off.
- Calls: Calls screen in Connect. Search an accepted friend, initiate a call, recipient accepts or declines. Audio/video controls start off and recipients cannot publish before accepting. Stranger and blocked-user calls are denied. Call invitations appear in the Calls list while the app is open and polling. Background ringing/push, operating-system call integration and missed-call history are not implemented. Room listings expire after two hours; explicitly end/leave sessions to disconnect media.
- Navigation: My Space is now Me. Header Back tracks page transitions; nested Gathering screens also have their existing Back to Gatherings control. Invite screen shares an app link plus an optional operator-issued pilot code. It sends no automatic messages and does not bypass invite-only signup. Shared invitation links prefill the code on the web signup form.
- Camera studio: browser capture supports Original, Vivid, Warm and Mono filters, physical green-screen replacement with a purple background, and a short caption burned into captured photos/videos. Green clothing can be replaced too; this is chroma key, not AI person segmentation. Effects videos include microphone audio and record from the processed canvas, up to five minutes/100 MB. Browser support varies. Native camera capture remains original media, with a link to the browser effects studio (sign in there if needed). Full embedded native effects are unfinished.
- Captions: Home media already has text overlays; Sparks now overlays its post text on the video. Camera-studio captions are baked into the captured media. Spoken subtitles remain the existing separate optional Mux caption feature.
- Admin panel: dashboard counts, existing service checks/account suspension/audit/report controls, default Gathering setup and an official-page marketing composer. Admin can attach their own photo or processed video and publish intentionally on the official Gather page. Public official video posts also appear in Sparks. No automatic publication was performed in this session.
- Private accounts: friend requests already require recipient approval. Private follow requests also require approval. No auto-accept behavior was added.

## Setup and verification

Use INSTALL-THIS-UPDATE.md for Windows/GitHub Desktop/Render installation. Keep your database/uploads/environment variables. New tables/columns are migrated automatically on startup. LiveKit must be configured for calls, voice and podcasts; Mux must be configured for product videos and marketing Sparks. New notification module requires a new native app build, not just a Render deploy. This ZIP has source/bundles, not signed installers.

65 automated tests pass, plus TypeScript and lint. Web/iOS/Android export checks are performed before delivery. Provider media, phones, browser camera recording, local alerts and UI layout require real-device testing. Payment checkout, actual gift purchases/sending, GC cashout, supplier fulfillment, native effects and background call ringing remain unfinished.

Posting camera flip: browser photo/video studio has a front/back Flip camera button, available during recording when the browser supports multiple cameras. It keeps the existing microphone and processed recording stream. Native posting has a front/back selector before opening the system camera; the Android camera app may ignore the requested initial camera. Actual multi-camera phone switching has not been tested.

## Posting controls and upload recovery (0.8.1)
Camera and Library actions now have separate headings and large labeled buttons. Upload and Publish are separate actions. Video selection clears the previous processing state; upload status is only marked ready after server confirmation. Missing file-size metadata is resolved from the selected file, and transfer failures include clearer connection, timeout, or HTTP messages. The shop uses the same size recovery.

Video troubleshooting: choose a local video up to 100 MB and five minutes. Select it, press Upload selected video, then Check video processing until ready, and Publish post. If uploads are not configured, add MUX_TOKEN_ID, MUX_TOKEN_SECRET, MUX_SIGNING_KEY_ID and MUX_SIGNING_PRIVATE_KEY to Render. PUBLIC_ORIGIN must be the exact browser origin (for example https://gatherourworld.com, without a path). For persistent errors, record the exact message and whether it happens during selection, transfer, processing, or publishing. These changes have not been deployed to your Render service or verified with your phone/Mux account.
